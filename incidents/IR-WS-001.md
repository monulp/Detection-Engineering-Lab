# Incident Response Report: Suspicious PowerShell Execution & Authentication Anomaly

## Incident ID
IR-WS-001

## Environment Overview
- **SIEM:** Splunk Enterprise (self-hosted lab)
- **Endpoint:** Windows 10 (WIN10-ENDPOINT)
- **Log Source:** Windows Security Event Log
- **Forwarder:** Splunk Universal Forwarder
- **Index:** windows_security

---

## Executive Summary
On **24 January 2026**, the SIEM detected suspicious PowerShell execution activity combined with abnormal authentication behavior on a Windows endpoint.  
The observed behavior matched common attacker techniques related to obfuscated command execution and credential abuse.

Following investigation, the activity was determined to be **benign system-generated behavior** originating from the Splunk Universal Forwarder service.  
No evidence of compromise or malicious activity was identified.

## Detection Details

### Detection 1: Encoded PowerShell Execution
- **Event ID:** 4688 (Process Creation)
- **Technique:** Obfuscated command execution
- **MITRE ATT&CK:** T1059.001 – PowerShell

**Observed Indicators**
- PowerShell executed with encoded command parameters
- Parent-child process relationship identified
- Execution occurred under a service account context

**Sample Fields**
- `NewProcessName`: splunk-powershell.exe  
- `ParentProcessName`: splunkd.exe  
- `SubjectUserName`: NT SERVICE\\splunkforwarder  

---

### Detection 2: Authentication Anomaly
- **Event IDs:** 4625 (Failed Logon), 4624 (Successful Logon)
- **Technique:** Brute Force / Password Spray pattern
- **MITRE ATT&CK:** T1110 – Brute Force

**Observed Indicators**
- Multiple failed authentication attempts
- Subsequent successful logon
- Network and service logon types involved

---

## Investigation and Analysis

### Initial Hypothesis
The combination of encoded PowerShell execution and authentication anomalies suggested potential post-exploitation or credential abuse activity.

---

### Investigation Steps
1. Reviewed process lineage and parent-child relationships
2. Analyzed command-line arguments for obfuscation or payload indicators
3. Verified user and service account context
4. Correlated authentication events around the execution timeframe

---

### Root Cause Analysis
The PowerShell executions were generated by **Splunk Universal Forwarder internal operations**.  
Authentication events were consistent with normal service behavior.

No attacker activity was identified.

---

## Impact Assessment
- No user accounts compromised
- No lateral movement detected
- No persistence mechanisms identified
- No data exfiltration observed

**Impact Level:** None

---

## Containment and Remediation
No containment actions were required.

**Recommended Improvements**
- Suppress alerts for known Splunk service PowerShell executions
- Maintain detection logic for encoded PowerShell executed by non-service accounts
- Improve time synchronization and ingestion latency
- Migrate future SIEM deployments to cloud-hosted infrastructure

---

## Lessons Learned

### What Worked Well
- Endpoint auditing was correctly configured
- SIEM ingestion pipeline functioned as expected
- Detection logic successfully identified high-risk behaviors
- Analyst workflow differentiated false positives from real threats

### Areas for Improvement
- Field extraction optimization for faster triage
- Alert tuning to reduce benign noise
- Improved time and ingestion consistency

---

## Final Incident Classification
**False Positive – Benign System Activity**
